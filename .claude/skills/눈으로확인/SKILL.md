# 띄워서 눈으로 확인

"될 것 같다"와 "된다" 사이에 이 스킬이 있다. 스크린샷을 보지 않고 다 됐다고 말하지 않는다.

## 1. 띄운다

```bash
python3 tools/serve.py 앱/<이름> --조용히 &
```

뜬 주소(기본 `http://127.0.0.1:8000/`)가 찍힌다. 8000번이 쓰이고 있으면 알아서 다음 번호로 간다.

`file://`로 바로 열어도 화면은 보이지만 서비스워커가 등록되지 않는다. 서버로 띄우는 쪽을 쓴다.

## 2. 찍는다

```bash
node tools/shot.mjs http://127.0.0.1:8000/ --out 화면/<이름>-목록.png
```

- `--전체` 스크롤 끝까지
- `--누르기 "<선택자>"` 눌러 본 뒤 찍기
- `--적기 "<선택자>=<값>"` 입력칸에 쳐 넣기
- `--기기 "iPhone 14"` 플레이라이트 기기 이름으로
- `--엄격` 콘솔 오류가 있으면 exit 1

`--누르기`와 `--적기`는 준 순서대로 실행된다. 화면 한 장이 아니라 **흐름**을 확인할 때 쓴다.

```bash
node tools/shot.mjs http://127.0.0.1:8000/ \
  --누르기 ".tabs a[data-tab=add]" --적기 "#text=우유 사기" --누르기 "button[type=submit]" \
  --out 화면/넣은뒤.png
```

넣은 것이 목록에 보이면 저장까지 된 것이다. 화면만 보고 저장됐다고 치지 않는다.

## 3. 콘솔을 읽는다

찍고 나면 콘솔 오류와 못 받아온 파일을 같이 찍어 준다. **`콘솔 깨끗함`이 나오지 않으면 화면이 멀쩡해 보여도 끝난 게 아니다.** 404 하나가 서비스워커를 조용히 죽인다.

## 4. 스크린샷을 실제로 본다

찍은 PNG를 **읽어서 본다**. 보지 않고 "찍었음"만 말하는 건 확인이 아니다. 볼 것:

- 위쪽 바에 제목이 가려지지 않았는가 (노치)
- 아래 탭이 본문을 덮지 않았는가
- 글자가 잘리거나 넘치지 않았는가
- 누를 것이 손가락만 한가 (44px)

## 5. 전후를 나란히 본다

```bash
node tools/shot.mjs --비교 화면/전.png 화면/후.png --out 화면/비교.png
```

고치기 전에 한 장 찍어 두는 습관을 들인다. 고친 뒤에 찍을 수는 없다.

## 6. 치운다

```bash
kill %1    # 서버 끄기
```

`화면/`은 작업용이다. 쌓이면 지운다.
