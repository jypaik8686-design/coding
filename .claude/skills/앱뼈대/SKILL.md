# 앱 뼈대 깔기

한 줄에서 시작해 돌아가는 앱 껍데기까지 간다. 순서를 지킨다. 코드부터 쓰면 화면 수가 계속 늘어난다.

## 0. 전제를 먼저 본다

한 줄 안에 폰 웹앱이 못 하는 일이 들어 있으면 깔기 전에 첫 문장으로 말한다. 깔고 나서 알면 다 버린다.

| 바라는 것 | 사실 | 그러면 |
|---|---|---|
| 폰을 바꿔도, 여러 기기에서 같은 데이터 | localStorage는 그 기기 그 브라우저에만 있다 | 서버가 있어야 한다. 이 틀의 범위 밖이라고 말하고, 내보내기(JSON)로 버틸지 묻는다 |
| 오래 안 열어도 데이터가 남기 | 아이폰 사파리는 7일 동안 그 사이트를 건드리지 않으면 localStorage를 지운다. 홈 화면에 추가한 웹앱은 예외다 ([WebKit](https://webkit.org/tracking-prevention/), 2026-11-12 확인) | 아이폰이면 홈 화면에 추가해서 쓰라고 말한다 |
| 앱을 닫아 놔도 알아서 뭔가 하기 | 웹앱은 닫혀 있는 동안 계속 돌지 못한다 | 열었을 때 밀린 일을 처리하는 꼴로 바꾼다 |

표에 없는 것은 기억으로 단정하지 않는다. 문서로 확인하고, 못 하면 확인 못 했다고 말한다. 걸리는 게 없으면 바로 1번으로 간다.

## 1. 한 줄을 세 가지로 쪼갠다

사용자 말에서 이것만 먼저 뽑는다. 추측하지 말고, 셋 중 빈 게 있으면 **그것만** 묻는다. 한 번에 다 묻지 않는다.

- **무엇을 담는가** — 항목 하나가 무엇인지 (할 일 한 줄 / 지출 한 건 / 책 한 권)
- **담아서 무엇을 하는가** — 보기, 넣기, 끝내기, 합계, 찾기 중 어느 것
- **혼자 쓰는가** — 혼자 쓰면 localStorage로 끝난다. 남과 나누면 그건 다음 앱이다

## 2. 데이터 모양을 먼저 적는다

화면보다 데이터가 먼저다. 항목 하나의 칸을 정한다. 칸은 적을수록 좋다.

```js
// 예: { id, text, done, at }
```

`id`와 `at`(만든 시각)은 거의 항상 필요하다. 나머지는 1번에서 뽑은 것만 넣는다.

## 3. 화면을 세 개로 묶는다

틀은 **목록 / 추가 / 설정** 세 칸으로 돼 있다. 대부분의 폰 앱은 여기에 들어간다.

- 들어맞으면 그대로 쓴다
- 네 번째 화면이 필요하면 `SCREENS`에 하나 더하고 `.tabs`에 탭을 하나 더한다
- 탭이 다섯 개를 넘으면 앱이 두 개다. 쪼개자고 말한다

## 4. 깐다

```bash
python3 tools/new_app.py <이름>
```

`앱/<이름>/`이 생긴다. 그다음 `앱/<이름>/명세.md`의 빈 칸을 1~3번에서 정한 것으로 채운다. 명세와 `app.js`의 `SHAPE()`는 같아야 한다.

## 5. 고친다

`app.js`에서 건드릴 곳은 두 군데뿐이다.

- `SHAPE()` — 데이터 모양
- `SCREENS` — 화면마다 HTML을 돌려주는 함수

라우터·저장·탭은 손대지 않는다.

## 6. 눈으로 본다

`눈으로확인` 스킬로 넘어간다. 스크린샷을 보기 전에는 됐다고 말하지 않는다.

## 7. 내놓는다

`내놓기` 스킬로 넘어간다. 폰에서 여는 주소를 건네야 끝난 것이다. 폴더에 파일이 생긴 것은 끝이 아니다.
