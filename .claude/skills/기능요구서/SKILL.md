# 기능 요구서

"넣고 싶음" 한 줄과 코드 사이에는 늘 결정 세 개가 숨어 있다. 그걸 먼저 끄집어낸다.

## 1. 요구를 네 칸으로 쪼갠다

말을 듣고 바로 이 표를 채운다. 못 채우는 칸이 질문거리다.

| 칸 | 묻는 것 |
|---|---|
| 데이터 | 새 칸이 생기는가, 기존 칸의 뜻이 바뀌는가 |
| 화면 | 어느 화면에서 보이고, 어디를 눌러 쓰는가 |
| 저장 | 기기에만 남는가, 밖으로 나가는가 |
| 안 함 | 이번에 하지 않을 것 |

**안 함 칸을 꼭 채운다.** 비워 두면 기능이 혼자 자란다.

## 2. 기존 데이터를 깨뜨리는지 본다

항목에 칸을 더하면, 이미 기기에 저장돼 있던 옛 항목에는 그 칸이 없다.

- 새 칸은 **기본값**을 정한다 (`i.tag ?? "없음"`)
- `SHAPE()`를 바꿨으면 `load()`의 펼치기(`{ ...SHAPE(), ...JSON.parse(raw) }`)로 메워지는지 확인한다
- 칸을 지우거나 뜻을 바꾸는 건 `KEY`의 버전을 올려야 하는 일이다. 사용자에게 "지금 저장된 게 날아간다"고 먼저 말한다

## 3. 명세에 적는다

`앱/<이름>/명세.md`의 표를 고친다. 코드와 명세가 어긋난 채로 두지 않는다.

## 4. 한 번에 하나만 고친다

데이터 → 화면 → 손질 순서로 간다. 세 개를 같이 바꾸면 무엇이 깨졌는지 모른다.

## 5. 눈으로 본다

`눈으로확인` 스킬로 전/후를 나란히 본다. 특히 **옛 데이터가 있는 상태**에서 확인한다 (새로 깐 앱에서는 2번 문제가 안 보인다).

## 6. 끝내기 전에

```bash
python3 tools/check_toolbox.py
```
