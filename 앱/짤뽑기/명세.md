# 짤뽑기 — 명세

## 한 줄

화풍·작가 프롬프트를 늘 붙여 NovelAI로 그림을 한 장씩 뽑고, 보관한 것과 버린 것에서 취향 태그를 쌓는다. NovelAI가 받는 생성 옵션(시드, 샘플러, 스텝, 크기, 인물별 프롬프트, 참고 그림, 이미지→이미지)을 화면에서 만지고, 뽑기 화면 안의 AI 도우미(제미니)가 프롬프트·자세·그림체·설정을 사용자 취향대로 짜 주고 그림을 보고 고쳐 준다. 쓸 만한 프롬프트는 프리셋으로 눌러 넣는다.

## 데이터 모양

`app.js`의 `SHAPE()`와 같아야 한다. 글자는 localStorage(`짤뽑기/v1`), 그림은 IndexedDB(`짤뽑기` v5 / `img`, `ref`, `src`, `pimg`, `vault`. v4에서 `pimg`, v5에서 `vault`만 더함). `KEY`는 그대로 `v1`: 새 칸은 전부 더하기만 했고 옛 칸의 뜻은 안 바뀌었다.

| 덩어리 | 칸 | 뜻 |
|---|---|---|
| settings | token / model / customModel / size / steps / scale / quality / qualityText / aiKey / aiModel / aiCustom | NovelAI 토큰과 생성 값. quality는 품질 태그를 붙이는지, qualityText는 7순위 품질 태그를 사용자가 고친 글(비면 모델별 기본 글 `qDefault`). size는 세로·가로·정사각. sampler / noise / cfgRescale / variety / customW / customH / refMode(vibe·precise)는 생성 옵션(크기 `직접`은 64 단위, 64~1536). aiKey는 제미니 키, aiModel은 `assistant.js`의 `MODEL_CHOICES` 중 하나 또는 `custom`(이름은 aiCustom). 옛 데이터에는 ai 칸이 없어 `load()`가 기본값으로 메운다 |
| taste | style / negative / seeded / negSplit | style은 늘 붙는 2순위 화풍·작가(처음 값은 `DEFAULT_STYLE` = art `프롬프트/NAI.md`의 키아나 그림체 블록). negative는 **기본 빼는 것**(모든 그림에 붙음, 처음 값은 NovelAI 문서의 Human Focus V5 Full). seeded는 style 처음 값을 이미 넣었다는 표시 — 옛 데이터에서 style이 비어 있으면 한 번만 채운다. negSplit은 빼는 것을 기본·이번으로 나눴다는 표시(2026-11-19): 옛 데이터의 negative에서 처음 기본 글에 없는 태그(프리셋·비서가 쌓은 것)를 `draft.neg`로 한 번만 옮긴다. 기본 글의 태그가 하나도 없으면(사용자가 통째로 바꾼 것) 옮기지 않는다 |
| draft | slots / scene / neg / seedLock / seed / seeded / chars / i2i | **neg**는 **이번 빼는 것**(2026-11-19): 프롬프트 칸처럼 프리셋(빼는 것·‘금지 태그도’)과 비서의 negative 블록이 넣는 곳이고 ‘칸 비우기’로 같이 비워진다. 보내는 빼는 것은 기본 + 이번을 이어 붙인 것(같은 태그는 한 번). 옛 데이터에는 없어 `""`(위 negSplit 옮김 제외). **slots**는 이번 그림을 칸으로 나눈 것 `{count(1순위 인원수·성별), traits(3순위 캐릭터 특징), outfit(4순위 의상·장신구), pose(5순위 포즈·시선·구도), bg(6순위 배경·조명·분위기·이펙트), rest(그 밖에: 칸을 못 나눈 글)}`이고, 2순위 화풍·작가는 `taste.style`, 7순위 품질 태그는 `settings.qualityText`(비면 모델별 기본 글)에 있다. **scene**은 slots를 이어 붙인 값으로 늘 맞춰 두어(`syncScene()`) 기록·보관함·통계가 그대로 읽는다. 옛 데이터(slots 없음)는 scene에서 인원수 태그(1girl, solo 등)만 1순위로 빼고 나머지를 ‘그 밖에’로 옮기며, 처음 기본 글과 같으면 칸으로 나눠 넣는다(글은 안 잃음). 쓰다 만 이번 그림, 시드 고정 여부, 마지막 시드. chars는 인물별 프롬프트 `[{id, text, neg, pos}]`(pos는 null=AI가 정함, 0~24=5x5 격자 칸, 최대 6명), i2i는 `{on, strength, noise}`(바탕 그림은 IndexedDB `src`). 처음엔 scene이 `DEFAULT_SCENE`(정장·중국식 미인·금발을 옮긴 태그)으로 채워져 있다. seeded는 이 기본값을 이미 넣었다는 표시 |
| log[] | id / scene / style / negative / seed / model / w / h / steps / scale / at / verdict / refs? / mode? / sampler? / noise? / cr? / vb? / chars? / i2i? / nd? / ext? / name? | 뽑은 기록 하나. negative는 보낸 빼는 것 전체, nd는 그때의 이번 빼는 것(옛 항목에는 없어 ‘다시 뽑기’가 negative에서 지금 기본 빼는 것을 뺀 나머지로 계산). ext는 밖에서 받은 그림(취향 통계에서 뺌), name은 받은 파일 이름. 받은 그림의 seed는 모르면 null. verdict는 null·keep·drop. 400건을 넘으면 보관 아닌 것부터 지운다. refs는 이 그림에 쓴 참고 그림 `[{s: 강도, i: 정보량}]`이고 옛 항목에는 없다(읽을 때 `?.`로 0장 취급). mode는 vibe·precise, sampler·noise·cr(cfg rescale)·vb(Variety+)·chars·i2i는 그림을 뽑은 옵션으로 ‘다시 뽑기’가 되돌린다. 바탕 그림·참고 그림 파일은 안 따라온다 |
| presets[] | id / name / text / to / kind / neg? / note? / at? | 사용자가 저장하거나 새로 만든 프롬프트. to는 scene·style·neg(어디에 넣는지). kind는 어느 탭에 보이는지(인물·의상·그림체·자세·구도·빼는 것·내 것, 옛 항목에는 없어 `normPresets()`가 "내 것"으로 읽음. 의상은 2026-11-19에 더함). slot은 scene 프리셋이 들어가는 칸. 탭에서 새로 만들면 to는 탭에 따라 정해지고(인물·의상·자세·구도→이번 그림, 그림체→화풍·작가, 빼는 것→이번 빼는 것), 인물은 at "front"(맨 앞에 더함). 뽑기 칸의 ‘프리셋으로 저장’은 캐릭터(1순위 인원수 + 3순위)→인물, 4순위→의상, 5순위→자세·구도로 저장한다. 내장 프리셋은 `presets.js` |
| presetEdits | `b:<종류>:<기본 이름>` → {name?, text?, neg?, note?, hidden?} | 내장 프리셋을 고치거나 숨긴 것. 고친 칸만 담고 기본과 같아지면 지운다(그래서 `presets.js`를 나중에 고치면 안 고친 프리셋에는 따라온다). 키는 기본 이름이라 이름을 고쳐도 안 바뀐다. 옛 데이터에는 없다 |
| persona | sections / extra / auto | 비서 지시문을 사용자가 고친 것. sections는 `assistant.js`의 기본 조각(역할·앱이 하는 일·프롬프트 설계 순서·대답 형식·자세·구도·그림체 잡기·태그 규칙·사용자 취향·모델 메모·긍정 표현만. 인물 고정 블록·이어 뽑기·한국어 답변 문체는 2026-11-19 사용자 요청으로 뺐고, 그 id `chars`·`series`·`korean`에 고쳐 둔 것은 읽을 때 버린다. 남은 조각의 id는 그대로) 중 **고쳤거나 끈 것만** `{<조각 id>: {text?, on?}}`로 담는다(안 고친 조각은 기본 글이 따라옴). extra는 사용자가 더한 조각 `[{id, name, text, on}]`(최대 20개, 지시문에 `## 이름`으로 붙음). auto는 앱이 지시문 뒤에 자동으로 붙이는 ‘앱 상태’·‘사전 후보’를 켜는지. 옛 데이터에는 없어 `normPersona()`가 기본값으로 메운다. 내보내기에 들어간다 |
| userDict | id / word / tags | 내 단어 사전. 낱말(한국어)과 태그(영어, 쉼표). 비서에게 한 말에 낱말이 들어 있으면 기본 사전보다 먼저 `[사전 후보]`에 `낱말 → 태그 (내 사전)`으로 붙는다. 기본 사전을 못 받아도 붙는다. 이 태그는 비서 답의 "사전에 없음" 검사에서 뺀다. 최대 300개. 옛 데이터에는 없어 처음 한 번 `STARTER_DICT`(정장·로우앵글·내려다보는·올려다보는·팔짱·턱 괴·왕좌·눈물·짜증·겁먹·오만·회사원·중국식·한푸·상반신·전신·클로즈업·돌아봄·옆모습)로 채우고, 그 뒤에 사용자가 다 지우면 다시 안 채운다. 처음 낱말의 태그는 기본 사전에 있고 게시물 1,000개 이상인 것만 골랐다(2026-11-18) |
| chat[] | role / text / at / done? | 비서와 한 대화. role은 user·model. done은 그 답에서 칸에 넣은 블록 번호 목록(2026-11-21, 옛 항목에는 없고 없으면 안 넣은 것으로 읽음). 40개를 넘으면 앞에서부터 버린다. 내보내기에는 들어가고 제미니 키는 빠진다 |
| (IndexedDB) img | id / full / thumb | 보관한 그림의 PNG 원본과 360px 썸네일. id는 log의 id |
| (IndexedDB) src | id("main") / name / full / thumb | 이미지→이미지 바탕 그림 한 장. 긴 변 1536px 이하 PNG |
| (IndexedDB) pimg | id / full / thumb / ref / at | 프리셋 대표 그림 한 장(2026-11-19). id는 프리셋 key(`own:<id>` 또는 `b:<종류>:<기본 이름>`), full은 긴 변 1024px 이하 PNG, ref는 그 프리셋을 ‘더하기’로 넣을 때 이 그림도 참고 그림으로 넣는지(같은 이름의 참고 그림이 이미 있으면 건너뜀). 내 프리셋을 지우면 같이 지운다 |
| (IndexedDB) vault | id / name / kind / label / size / at / src / blocks | 보관소(2026-11-19). 받은 프롬프트·파일을 파일 안의 블록 그대로 펼친 것 `blocks:[{title, kind, text, meta?}]`. 펼치는 코드는 해체기의 `risu.js`를 `../해체기/risu.js`로 불러 씀(해체기 폴더를 옮기면 import도 고쳐야 함). 원본 파일은 안 남김 |
| (IndexedDB) ref | id / name / at / on / strength / info / fid / kind / full / thumb / enc | 참고 그림. full은 긴 변 1024px 이하 PNG, strength는 0~1(처음 0.6), info(정보량)는 0~1(처음 1), on은 이번에 쓰는지. enc는 `{"<모델>\|<정보량>": 인코딩 결과(base64)}`로, 같은 그림·모델·정보량이면 서버에 다시 안 묻는다. fid는 정밀 참조의 충실도(0~1, 처음 0.5), kind는 `character&style`·`character`. 최대 4장(이 앱이 정한 한도) |

## 밖에 나가는 것

- NovelAI: `POST https://image.novelai.net/ai/generate-image`, 그리고 참고 그림이 있을 때만 `POST https://image.novelai.net/ai/encode-vibe`. 토큰은 `Authorization: Bearer`로 이 서버에만 간다.
- 제미니: `POST https://generativelanguage.googleapis.com/v1beta/models/<모델>:generateContent` (그림을 같이 보낼 때만 `inline_data` JPEG, 긴 변 768px. 방금 뽑은 그림이거나 사용자가 고른 사진 한 장이고, 두 모델 이름 4개 모두 그림 입력을 받는 것을 2026-11-18 직접 호출로 확인). 키는 `x-goog-api-key` 머리글로 이 서버에만 간다. 비서에게 보낸 대화, 취향 프롬프트, 현재 이번 그림 칸, 비서 지시문이 구글로 나간다. 이 서버가 브라우저 직접 호출을 허용하는 것은 사전 요청으로 확인했다(2026-11-18, `access-control-allow-origin`이 요청 출처를 되돌려 줌).
- 이 서버는 브라우저 직접 호출을 받는다: 사전 요청에 `access-control-allow-origin: *`, 허용 헤더 `Authorization, Content-Type` (2026-11-15 curl로 확인).
- NovelAI로 가는 글은 칸을 1→7순위로 이어 붙인다(2026-11-18, 사용자가 칸 나누기를 요청): 인원수·성별, 화풍·작가(취향 프롬프트), 캐릭터 특징, 의상·장신구, 포즈·시선·구도, 배경·조명·분위기·이펙트, (그 밖에), 품질 태그. 같은 태그는 먼저 나온 것만 남긴다. 예전에는 이번 그림, 취향, 품질 순이었다. 순서가 바뀌어 같은 글이어도 결과 그림이 달라질 수 있고, 이 순서가 그림에 더 낫다는 것은 비교해 보지 않았다(NovelAI는 앞쪽 태그를 더 세게 읽는 경향이 있다고 알려져 있으나 이 앱에서 재 보지 않음).
- 프리셋은 자기 칸에만 들어간다: 인물은 인원수 태그를 1순위로, 나머지를 3순위 앞에, 자세·구도는 5순위, 내 프리셋은 고른 칸(기본 ‘그 밖에’). ‘바꾸기’도 그 칸만 바꾼다. 비서의 scene 블록은 `count:` `traits:` `outfit:` `pose:` `bg:` 줄로 쓰고, 블록이 이번 그림 전체를 대신하므로 줄이 없는 칸은 비워진다. 줄 이름 없는 옛 형식은 인원수 태그만 1순위로, 나머지는 ‘그 밖에’로 들어간다. 복사 버튼은 줄 이름을 뗀 한 줄 글을 복사한다.
- 요청 몸통은 V5에서 200이 확인된 꼴을 그대로 쓴다. `v4_prompt`·`v4_negative_prompt`를 빼면 500. 응답은 `image_0.png`가 든 zip ([측정 글](https://dev.to/ilan_kim/calling-the-novelai-v5-api-directly-nai-diffusion-5-full-request-body-paramsversion-4310-133a), 2026-11-15 읽음). 틀린 토큰은 `401 Unauthorized` (2026-11-15 curl로 확인).
- 품질 태그 문구는 [NovelAI 문서](https://docs.novelai.net/en/image/qualitytags/) 그대로. 서버 토글(`qualityToggle`)은 끄고 앱이 직접 붙인다.
- 참고 그림(V4.5 바이브): 그림을 `/ai/encode-vibe`에 `{image(base64 PNG), information_extracted, model}`로 보내면 이진 파일이 오고(2026-11-18 200 확인, 문서에는 201), 이것을 base64로 바꿔 `reference_image_multiple`에, 정보량을 `reference_information_extracted_multiple`에, 강도를 `reference_strength_multiple`에 같은 순서로 넣는다. 이 꼴로 V4.5 Full에서 한 장이 나왔고 참고 그림의 검정·금테가 결과에 따라왔다(세션에서 `curl`로 확인). 인코딩 비용 2 Anlas는 문서 기준이고 실제 차감은 재 보지 않았다.
- 생성 옵션은 2026-11-18 세션에서 `curl`로 V4.5 Full에 하나씩 보내 200을 받았다: 샘플러 `k_euler`·`k_euler_ancestral`·`k_dpmpp_2s_ancestral`·`k_dpmpp_2m`·`k_dpmpp_sde`·`k_dpmpp_2m_sde`(`ddim_v3`와 틀린 이름은 500), 노이즈 스케줄 `karras`·`exponential`·`polyexponential`·`native`, `cfg_rescale`, `skip_cfg_above_sigma: 19`(Variety+), 인물별 프롬프트+`centers`(V4.5와 V5 둘 다 그림에서 위치가 따라옴), `action: "img2img"`+`image`·`strength`·`noise`, 정밀 참조(`director_reference_*`, 1024×1536 검은 여백). 결과 그림은 눈으로 봤지만 옵션마다 화질이 어떻게 달라지는지는 비교하지 않았다.
- 확인 못 한 것: 스텝 29 이상과 1024×1024 초과 크기(상한 50·1536은 이 앱이 정한 값, Anlas 차감도 재 보지 않음), Variety+의 값이 NovelAI 화면과 같은지, 정밀 참조 5 Anlas와 인코딩 2 Anlas의 실제 차감, 아이폰 사파리.
- V5(`nai-diffusion-5-full`)는 참고 그림이 서버에서 거절된다(art 확인 2026-11-17). 그래서 모델이 V5이면 붙여 둔 그림이 있어도 안 보낸다.
- 비서가 쓰는 제미니 모델은 2026-11-18 이 키로 직접 불러 200을 받은 것만 고르기에 둔다(`gemini-flash-latest`, `gemini-3.8-flash`, `gemini-3.1-pro-preview`, `gemini-4-argon`(아르곤: 같은 날 글과 그림 첨부 둘 다 200, 비서 지시문으로 scene 블록도 나옴. 모델 목록에는 `gemini-4-carbon`·`gemini-4-hydrogen`도 있으나 이 앱에서는 불러 보지 않아 고르기에 안 둠)). `gemini-2.5-flash`와 `2.5-pro`는 모델 목록에는 있는데 호출하면 "새 사용자에게는 더 안 열림"으로 404였다. 사용자 키에서는 다를 수 있어 ‘직접 입력’을 둔다.
- 프리셋(`presets.js`): ‘확정’은 art `프롬프트/NAI.md`·`NAI사용법.md`에서 옮긴 것(인물 4, 키아나 그림체, 빼는 것 5). ‘가안’(화보 애니풍 등 그림체 4, 자세·구도 11)은 `취향.md`의 낱말을 이 앱이 사전 태그로 옮긴 것이고 태그마다 `tags.json`의 게시물 수를 확인했다(없는 태그·1000개 미만은 뺌).
- 저장이 실패하면(localStorage가 참) 화면 맨 위에 경고가 뜬다. 예전에는 콘솔에만 남았다. 실제로 저장 공간이 찬 폰에서는 재 보지 못했고, 저장이 예외를 던지게 만든 시험으로만 확인했다.
- 비서 지시문은 앱의 지금 기능을 알고 쓰도록 맞춰 두었다(2026-11-18): 프리셋(이름은 `## 앱 상태`의 프리셋 줄로 매번 넘어감, 숨긴 것은 빠짐), 내 단어 사전의 `(내 사전)` 후보(게시물 수 검사 없이 그대로 쓰고, 후보에 없는 낱말은 지어내지 않고 단어 사전에 더하라고 알림), 블록 버튼이 칸을 바꾸는 방식(scene은 이번 그림 전체 교체, style·negative는 영구, char는 더하기뿐이라 이미 있는 인물을 고치려면 그 칸을 먼저 지우게 안내), 보관·버림은 사용자 몫. 앱에 기능이 늘면 `assistant.js`의 `## 앱이 하는 일`과 `stateText()`를 같이 고친다.
- 비서 지시문에 `## 프롬프트 설계 순서` 조각(id `design`)을 두고 설계 기준을 V4.5 Full로 못 박았다(2026-11-18, 사용자가 준 ‘NAI 프롬프트 디렉터’ 규칙을 합침. 원문은 `Claude-` 저장소 `페르소나/NAI프롬프트디렉터/`): 취향·의도 풀기 → 단부루 태그 맞추기 → 배치 순서(인원수·성별, 인물 특징, 의상, 포즈·구도, 배경·조명) → 가중치(`{}`는 3중까지, 더 세게는 `::` 배율) → 맞춤형 빼는 것. 대답 첫머리에 설계 의도 3줄 이내, 코드 블록 안에는 한글 설명을 넣지 않는다. 그 글의 출력 형식(설계 의도 + Positive 두 칸)과 V3 기준, 화풍·작가·품질 태그를 프롬프트 안에 쓰라는 순서는 따르지 않았다(앱이 취향 프롬프트와 품질 태그를 뒤에 붙이고, 코드 블록 형식이 ‘넣기’ 버튼을 움직이기 때문). 지시문 조각을 직접 고쳐 둔 사용자는 그 조각에 새 기본 글이 안 들어오니 ‘이 조각 기본값으로’를 눌러야 한다.
- 비서 지시문 끝에 조각 셋을 더했다(2026-11-18, 사용자가 준 RisuAI 롤플레이 프리셋·모듈 `마나젬 잼4 카본`·`Stage of Tales`·`한출 보조`에서 그림 프롬프트에 쓸 수 있는 기법만 새로 써서 옮김, 원문 번역 아님): `긍정 표현만`(없음·반대를 말하는 표현 대신 있어야 할 것을 쓰고 없앨 것은 빼는 것으로), `이어 뽑기`(고정할 것과 바꿀 것을 나눠 한 번에 둘 이하만 바꾸고 다음 변화 하나를 제안), `한국어 답변 문체`(번역투·대비 말투·느낌표 금지, 다른 문자 섞지 않기). id는 `affirm`·`series`·`korean`이고 맨 뒤에만 더해서 옛 조각 id는 안 밀린다. 옛 데이터에도 새 조각은 기본 글로 켜져 들어가고, 안 쓸 조각은 ‘비서 지시문 고치기’에서 끈다. 롤플레이용 탈옥·성인 조각, 인물 심리 분석(SoT 본체), 정규식 보정 278개, 장르·전개 속도 토글은 그림 프롬프트에 맞지 않아 옮기지 않았다. 제미니 호출 한 번(`gemini-flash-latest`, 새 조각 + 역할·대답 형식만 보냄)에서 ‘장갑 없이·웃지 않게’가 `bare hands, -1::gloves::`·`expressionless`로 바뀐 것은 봤지만, 조각이 있을 때와 없을 때 그림이 더 나아지는지는 비교하지 않았다. 2026-11-19 사용자 요청으로 이 가운데 ‘이어 뽑기’·‘한국어 답변 문체’와 원래 있던 ‘인물 고정 블록’을 뺐다. ‘긍정 표현만’은 남김.
- 비서 지시문(`assistant.js`)은 art 저장소의 `취향.md`, `프롬프트/NAI.md`, `프롬프트/NAI사용법.md`에서 그림 프롬프트 만들기만 옮긴 것이다(2026-11-18). art가 바뀌어도 자동으로 안 따라온다.
- `tags.json`의 한국어 낱말은 2,163개뿐이고 이 사용자가 쓰는 말(킅순이·키아나·정장·로우앵글·내려다보는·오만·굴욕·왕좌·중국식·회사원 등)은 대부분 없었다(2026-11-18 확인, 금발만 있음). 그래서 비서가 이런 낱말을 사전에서 못 찾았고, 내 단어 사전(`userDict`)을 두었다. 인물 이름은 비서 지시문의 인물 고정 블록이 맡는다.
- 태그 사전(`tags.json`, 약 430KB·압축 170KB)은 art `태그사전/`의 일반 태그(게시물 100개 이상 17,267개)와 한국어 이름 2,163개를 옮긴 것이다. 비서 화면을 처음 쓸 때 한 번 받는다. 한국어 낱말이 들어 있으면 그 태그를 ‘사전 후보’로 제미니에 붙이고, 비서가 낸 scene 블록의 태그는 사전과 맞춰 없는 것·1000개 미만인 것을 알린다. 캐릭터·작가 이름과 `young adult woman` 같은 문장형 문구는 일반 태그에 없어서 ‘사전에 없음’으로 나온다.
- 받은 그림(2026-11-19): NovelAI PNG의 tEXt 청크 `Description`(프롬프트)·`Source`(모델)·`Comment`(생성 정보 JSON: prompt·uc·seed·steps·scale·sampler·noise_schedule·cfg_rescale)를 읽는다. 청크 이름은 novelai-sdk-unofficial 문서와 NAIWeaver 변경 기록에서 확인했고, Comment 안의 키 이름은 진짜 NovelAI PNG로는 확인 못 해서 `uc`·`negative_prompt`·`v4_negative_prompt` 셋을 같이 본다. 시험은 이 키로 만든 합성 PNG로만 했다. 압축된 iTXt는 안 읽는다. 받은 그림의 프롬프트는 칸을 나누지 못해 인원수만 1순위로, 나머지는 ‘그 밖에’로 들어가고, ‘다시 뽑기’는 지금 화풍·작가를 같이 붙인다.
- 기록 JSON 되살리기(2026-11-19): ‘기록 내보내기’ 파일을 읽어 `normAll()`(저장값을 읽을 때와 같은 옛 데이터 보정)로 맞춘 뒤, 기록·내 프리셋·내 단어·고친 내장 프리셋은 더하고(같은 id·낱말은 건너뜀), 화풍·작가·기본 빼는 것·비서 지시문은 불러온 값으로 바꾼다. 토큰·키·지금 칸·대화는 그대로. 확인창을 거치고, 알림의 ‘되돌리기’(9초)로 통째로 돌린다. 그림은 JSON에 없어서 보관함에 ‘그림 없음’ 칸으로 보인다.
- 진짜 토큰으로 이 앱의 화면에서 그림이 나오는 것은 돌려 보지 못했다. 가짜 서버로 흐름을 확인했고, 요청 꼴은 세션에서 `curl`로 따로 확인했다.

적어 두면 나중에 흔들리지 않는다.

- 로그인, 서버 저장, 기기 사이 동기화
- 자동 반복, 자동 재시도 (NovelAI는 사람이 누른 요청만 허용하고 429에 재시도를 금한다)
